# Version 0.6 resource soak — 2026-08-30

This run exercised the installed version 0.6/build 10 lossless whole-frame
DPCM sender and receiver on the target MacBook and exact 2017 27-inch iMac. It
was stopped after 1,201 seconds as a **qualified early failure**. By then the
receiver had reproduced a deterministic post-warm-up resident-memory staircase
above the project's +2 MiB/hour release gate. That observed window failed the
gate and warranted stopping, so the samples were preserved and the redundant
periodic power call was removed before starting version 0.7.

This is diagnostic evidence, not immutable release proof. The collector
recorded source revision `01b0f6290379d1729ab7fc8e822690974d68fb8b` with
`worktree=dirty`. The exact installed executable identities were:

- MacBook sender SHA-256:
  `7c42354be31cd95af59c4c2d2f0e08c4c0bf9dfa6e5db0a0c66543dc2b181ffe`;
- iMac v0.6/build 10 receiver SHA-256:
  `617029755fb51c97f14ded0dd3a1b938b17fc3753c581ddd72606af4fec589d9`.

The privacy-scrubbed samples are in
[`2026-08-30-v0.6-resource-soak.tsv`](2026-08-30-v0.6-resource-soak.tsv).
All 21 samples found both processes running. Bundle, Application Support, and
log sizes were exactly flat; no frame data was written to disk. Thread and file
descriptor counts stayed bounded, and neither Mac reported a thermal or
performance warning.

The receiver stayed flat at 99,552 KiB from 120 through 600 seconds. At 660
seconds it allocated a 1,040 KiB page batch; thereafter it climbed by roughly
80–84 KiB each minute. A live `pmset -g assertions` snapshot then showed its
`UserIsActive` assertion only 29 seconds old even though the receiver had been
running for more than 22 minutes. That directly confirmed that the receiver
was renewing `IOPMAssertionDeclareUserActivity` once per minute.

Apple documents `IOPMAssertionDeclareUserActivity` as a wake/postpone signal
and `PreventUserIdleDisplaySleep` as the assertion for holding a display awake.
Version 0.6 already held the latter for the entire stream, so renewing the
former on every heartbeat was redundant. It also matched the allocation
cadence. This correlation is not proof that IOKit leaked an assertion, but the
call had no required power-management job and was removed independently of the
memory result.

Version 0.7/build 12 now uses the external-display lifecycle: create one
display-sleep assertion, declare remote user activity once to wake the panel,
perform no power calls per frame or heartbeat, and release both IDs at session
end. A fault-injected unit test covers 25 reconnects, idempotent teardown, and
create/declaration failure rollback. Version 0.7 requires its own complete
one-hour soak and human physical-screen acceptance; this v0.6 result is not
reused as proof.

# Version 0.7 diagnostic resource run — 2026-08-30

Version 0.7/build 12 removed the redundant once-per-minute user-activity
renewal. A live `pmset -g assertions` check at 8 minutes 55 seconds confirmed
that the original `UserIsActive` ID had not been replaced: its age matched the
display assertion's age. This falsified the hypothesis that the periodic power
call was the only source of the resident-memory ramp.

The privacy-scrubbed samples are in
[`2026-08-30-v0.7-resource-soak.tsv`](2026-08-30-v0.7-resource-soak.tsv).
This was intentionally stopped after 540 seconds and is **diagnostic only**,
not a qualification run. The collector recorded source revision
`01b0f6290379d1729ab7fc8e822690974d68fb8b` with `worktree=dirty`. The exact
installed receiver SHA-256 was
`e2809165f2781708e96f18517ade3db23e36b018c015bc6911a56540df63eee2`.

Before invasive diagnostics, receiver RSS rose from 98,368 KiB at launch to
99,000 KiB at 300 seconds while its thread, descriptor, and on-disk counts were
flat. Source inspection identified the dominant expected ramp: persistent mode
allocated two zero-filled 36,000-element `double` arrays, then dirtied their
pages frame by frame for the first ten minutes. At 60 FPS, the two eight-byte
samples alone touch about 56.25 KiB per minute before allocator/page effects.
That memory was bounded, but it made the release-gate graph resemble a leak and
retained stale startup telemetry in an all-day process.

At approximately 371 seconds, `heap` and `vmmap` were deliberately run against
the process to classify the allocation. That inspection perturbed its resident
set, so the later values and fitted +10.009 MiB/hour full-window slope are not
valid acceptance evidence. The snapshots still showed fixed 64 MiB receive
buffers, fixed Metal/IOSurface pools, and 20,447 live heap nodes rather than an
unbounded frame cache.

Version 0.8/build 13 replaces the first-ten-minute arrays with two rolling
600-frame rings—roughly ten seconds of recent packet/gap telemetry and about
9.4 KiB total. It also retains and retries any assertion ID whose IOKit release
fails, and refuses a new session until unresolved session assertions are
released. Version 0.8 requires its own unperturbed one-hour run; no v0.7 number
is promoted as release proof.

# Version 0.9 lifecycle candidate — 2026-08-30

Version 0.9 addresses the failure exposed by the completed v0.8 soak: a
securely locked iMac had no presentable Aqua surface, yet both peers continued
capturing, encoding, transporting, decoding, and submitting 5K frames.

This record is a **receiver deployment and control-plane qualification**, not a
paired video-stream release pass. The owner was asleep, so the rebuilt sender
was intentionally not installed: changing its ad-hoc code identity can require
one foreground Screen Recording approval, and the project does not automate or
reset TCC consent.

## What changed

- optional receiver-surface (`0x39`) and source-display (`0x3A`) packets with
  monotonic epochs and an ordered receiver-epoch acknowledgement barrier;
- capture, DPCM/Metal, audio, and frame-network work pause while either source
  or receiver display surface is unavailable, while the virtual display,
  arrangement, and control connection remain alive;
- a black privacy cover, balanced local-cursor ownership, and display-awake
  assertion are all fail-closed behind public AppKit/NSWorkspace state;
- a newly usable surface remains covered until a frame from its exact current
  presentation generation actually completes;
- launch during an already locked session uses a read-only console snapshot,
  requires explicit unlocked evidence, does not wake the panel, and performs
  only bounded generation-cancelled recovery retries;
- malformed, signed, stale, conflicting, or overflowed lifecycle epochs and
  malformed/ambiguous console records cannot authorize pixels or cursor hiding;
- fixed receive slots, cached drawable geometry, bounded rolling timing data,
  and non-allocating hot-path renderer statistics preserve the resource bounds.

The receiver intentionally retains one `PreventUserIdleSystemSleep` assertion
while waiting so it remains reachable as a display appliance. It does not hold
`UserIsActive` or `PreventUserIdleDisplaySleep` while idle, so the panel may
sleep and no cursor is hidden. This is an explicit availability-versus-idle-
power tradeoff, not a leak.
